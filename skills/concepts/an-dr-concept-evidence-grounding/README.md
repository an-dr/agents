# an-dr-concept-evidence-grounding

The principle behind every "do not fabricate" rule: each conclusion traces to evidence, and the reader can tell what was seen from what was guessed.

## When it runs

A concept is read, never run. Skills load it whenever they write or judge something that states facts: a report, review, overview, README, test result, or diagnosis.

## How it works

Every statement has one kind, made visible wherever it could be mistaken for another.

| Kind     | Basis                                                          |
| -------- | -------------------------------------------------------------- |
| Observed | Read or run in this session                                    |
| Derived  | Calculated from observed values, with the inputs named         |
| Inferred | Reasoned from observations, with the reasoning shown           |
| Assumed  | Taken as true without checking, and labelled so                |
| Intended | What a requirement or document says should be true — not proof |

- A claim with nothing behind it is cut, marked assumed, or turned into a question.
- An unrun check is reported as unrun; plausible is never presented as verified.
- Coverage is stated, so an empty finding list is not mistaken for a clean bill.
- Documentation and code that disagree are reported as a disagreement, not quietly reconciled.

## What you get

Output you can trust in proportion to its evidence: invented paths, unrun "tests pass", and summaries stronger than their findings are violations.
