# Page

## Sections

1. Scope and provenance: inspected areas, exclusions, sampling limits.
1. Short conclusion with counts by priority; none substantiated → say so, no manufactured rows.
1. Findings table sorted by priority and consequence, columns **ID**, **Priority / basis**, **Evidence and problem**, **Human impact**, **Proposed change**; link an ID to its detail section when it needs more space.
1. Details keyed by ID: locations, reasoning, constraints the fix must preserve, a way to verify the change; observed behaviour separated from inference.
1. Checks performed, limitations, unresolved questions. Sound areas stay quiet.

Diagrams only when they explain a structural issue better than prose.

## Verify

- Escape repository text before inserting it into HTML.
- Every finding has a unique ID, priority, evidence, and an actionable proposal.
- Table rows and details agree.
- Table readable in both themes and at phone width.
- State whether visual verification is complete or blocked; report generation or an overflow measurement alone does not finish it.
