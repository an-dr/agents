# C4 levels

Level 4 is the code itself; draw 1 to 3.

| Level         | Answers                                                                                         | Derived from                                                                                                                          |
| ------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 1 — Context   | What the system is, who uses it, what it talks to that it does not own                          | outbound calls, SDK and client dependencies, credentials and endpoints in configuration, webhooks, schedulers                         |
| 2 — Container | What separately runs or deploys, in what language, over what                                    | entry points, `Dockerfile` and compose files, deployment manifests, CI jobs, process definitions, workspace members, ports and queues |
| 3 — Component | Major groupings inside the container the reader will work in, and how they depend on each other | directory structure confirmed by the import graph, not directory names alone                                                          |

- Desktop application, CLI, or library: the container level is the declared binaries, compiled guest artifacts, packaging scripts, and helper processes the main one spawns; the scan reports these separately.
- Only what the code confirms is drawn. A documented container missing from the repository is a drift row, not a box.
- A box from an inferred grouping is labelled inferred.
- Level 3 container: the one with the most churn; the page says why it was chosen.
- One component diagram; a second only when the reader will genuinely work in both.
